## 2. 진행 원칙과 권장 구조

**추천 순서: 계약과 데이터 → 인증 → 화면 골격 → 수동 저장 흐름 → AI → 다양한 입력 → 프로젝트 → 검색 → 브리핑 → 확장.**
AI보다 저장·수정·조회 흐름을 먼저 만들면 AI 응답이 불안정해도 앱 자체를 검증할 수 있다.

- 플랫폼 제안: 반응형 웹 우선. 기존 TypeScript를 재사용하기 쉽다. 네이티브 앱이 필수라면 단계 0에서 확정하고 화면·녹음·잠금 어댑터만 바꾼다.
- 추천 분리: 화면 / 도메인 로직 / API 연결 어댑터 / 서버·저장소 / 비동기 작업자. 현재 src/auth·onboarding·review·shared는 유지한다.
- 예정 경로(스택 확정 후 조정): src/contracts/, src/adapters/, src/domain/, src/ui/, server/, tests/integration/, tests/e2e/.
- MyClaw는 규칙·타입·가짜 서버·단위 테스트를 먼저 만들 수 있다. 실제 화면·백엔드가 없으면 통합 완료에서 멈춘다.
- 화면/API 담당이 따로 있으면 인터페이스 계약과 테스트 데이터를 전달한다. 같은 저장소에서 MyClaw가 맡는 경우에도 역할별 결과를 구분한다. 담당자는 아직 미정이다.
- 비용 기본 0원: 가짜 응답·로컬 DB·로컬 메일함·소규모 로컬 모델로 우선 개발. 실제 이메일·푸시·AI·호스팅의 무료 한도와 라이선스는 선정 시 확인한다.
- 가짜 응답 통과를 실제 AI 품질·메일 수신·알림 도착 성공으로 보고하지 않는다. 유료 서비스 및 외부 데이터 전송은 사전 합의 전 실행하지 않는다.

- MyClaw: 태그·프로젝트·담당자 연결, 프로젝트별 메모/파일/할 일 모으기, 진행률 계산 규칙.
- 화면/서버: 멤버 검색·유효성 검증, 할 일 배정·저장, 참여 인물/진행률 표시.
- 완료 기준: 실제 참여 멤버만 배정, 타 프로젝트·타 계정 접근 차단, 진행률·연결 정보 갱신.
- 태그만 먼저 구현할 수 있지만 프로젝트·담당자가 빠진 상태는 REQ-INB-002 전체 완료가 아니다.

### 단계 7 — 저장 정보 기반 AI 비서
- 선행: 단계 3~6 데이터·검색 권한·원본 링크, 음성 질문은 단계 5.
- MyClaw: 질문 상태·대화 기록 정책·검색/답변 어댑터·출처 표시 및 이동.
- 서버: 사용자 권한으로 검색한 자료만 답변 근거로 사용, 원본 ID/위치 반환, 삭제 자료 색인 제거.
- 완료 기준: 텍스트/음성 질문→저장 정보 답변→실제 원본 이동. 근거가 없으면 없다고 안내하고, 타 계정 및 삭제 자료를 노출하지 않는다.
- 품질 검증: 검색 정확도·출처와 답변 일치·원문 속 악의적 지시 무시. 답변 생성 성공과 사실성은 별도로 측정한다.

### 단계 8 — 일간 브리핑·실제 알림
- 선행: 단계 2 설정, 단계 3 집계, 인증된 전송 채널 및 지속 실행되는 서버 작업자.
- MyClaw: 시간대별 예정 시각, 요약 대상 계산, 작업 중복 방지, 실패 재시도 테스트.
- 서버: 설정 변경/해제 시 예약 갱신, 재시작 후 복구, 일간 발송·일정 알림 전달 및 발송 이력.
- 완료 기준: 테스트 시계로 시간대·자정·변경·중복·재시작 검증 후 실제 기기에서 알림 도착 확인. 앱이 닫혔을 때도 확인한다.
- 주간 브리핑은 설정 요구사항만 있다. 실제 주간 생성/발송을 추가할지는 별도 합의하며 50건에 몰래 포함하지 않는다.
- 이 단계는 제품 내부 예약 기능 개발이다. MyClaw의 개발 알림용 크론 등록 요청이 아니므로 이번에는 schedule_task를 호출하지 않는다.

### 단계 9 — 회의 교차 대조·선제 알림
- 선행: 단계 4~5 문서/회의 분석, 단계 6 관련 프로젝트, 단계 8 실제 알림.
- 지원 작업: 사전 문서와 회의 연결, 안건·논의 결과·미해결 상태의 데이터 계약.
- MyClaw/서버: 사전 안건↔회의 근거 비교, 변경/미논의 구분, 관련 일정 전 필요한 정보 선택.
- 완료 기준: 정답을 마련한 회의 예제에서 변경과 미논의 구분·양쪽 근거 확인, 알림 중복/해제/무관한 안건 차단.
- 추출 실패를 “논의되지 않음”으로 단정하지 않는다. 품질 기준과 알림 시점은 구현 전에 합의한다.

### 단계 10 — 소셜 로그인·기기 내 AI·앱 잠금
- 선행: 단계 1 인증, 단계 4~5 분석 계약, 플랫폼별 기술 검증.
- 소셜 로그인: 제공자 선정→무료 개발 앱 등록→로그인/가입·기존 이메일 충돌·연동 정책→실제 콜백 테스트.
- 기기 내 AI: 대상 기기에서 모델 크기·속도·메모리·정확도·라이선스 검증→지원하는 분석만 선택 가능하게 구현.
- 기기 처리 선택 시 임의로 외부 서버로 보내지 않는다. 미지원/실패 시 명시적 안내와 사용자 선택을 제공한다.
- 앱 잠금: 비밀번호/플랫폼 생체 인증, 백그라운드 복귀 잠금·실패·복구·민감 캐시 정책. 웹의 WebAuthn 인증을 OS 전체 앱 잠금과 동일시하지 않는다.
- 완료 기준: 실제 제공자·실제 기기 검증. 불가능/미지원 조합은 기술 검증 결과와 남은 요구사항을 기록한다.
- 로컬 AI·잠금의 기술 조사만 단계 0에서 앞당길 수 있다. 전 기능 구현을 먼저 시작하지 않는다.

## 5. 팀 결정이 필요한 지점과 임시 대응

지금 계획서를 만들기 위해 모든 결정을 묻지는 않는다. 해당 단계 착수 때 필요한 것만 확정한다.

| 결정 | 시점 | 합의 전 할 수 있는 것 |
|---|---|---|
| 웹/앱, 화면·서버 담당, API 연동 저장소 | 단계 0 | 플랫폼 독립 타입·규칙 정리 |
| 인증 정책, 약관 내용, 메일 서비스 | 단계 1 | 가짜 API와 오류/만료 테스트 |
| AI 자동 저장 허용 기준·기본 설정 | 단계 2/4 | 모두 검토하는 흐름 및 설정 계약 |
| 마감 임박 기간·중요 메모·관련 메모 기준 | 단계 3 | 정책을 주입하는 공통 계산 함수 |
| 반복 일정 수정 범위·시간대·휴지통 보관 기간/만료 후 처리 | 단계 3 | 설정 가능한 규칙과 경계 테스트 |
| 파일 제한·AI 서비스·외부 전송 동의 | 단계 4/5 | 가짜 작업·로컬 예제 |
| 팀원 초대/권한·진행률 계산 | 단계 6 | 가짜 멤버 및 권한 테스트 |
| 알림 채널·주간 실제 발송 추가 여부 | 단계 8 | 가짜 시계·중복 방지 |
| 회의 비교 품질 기준·선제 알림 시점 | 단계 9 | 정답 예제 준비 |
| 소셜 제공자·로컬 AI 지원 기기·잠금 방식 | 단계 10 | 기술 조사·작은 실험 |

- 원문에 없는 숫자는 확정하지 않는다. 예: 30일 보관·15분 전 알림·자동 저장 신뢰도는 기존 자료에 있더라도 이번 목록의 확정 조건이 아니다.
- 일정/기간: 마감·인원·하루 투입 시간·플랫폼 미정이라 완료 날짜는 미산정. 단계 0 뒤 작은 첫 묶음의 실측으로 재산정한다.
- 주요 위험: 플랫폼별 녹음/알림 제약, 무료 서비스 제한, 로컬 AI 성능, 회의 비교 정확도. 각각 실제 기기·서비스·평가 예제로 해소한다.

## 6. MyClaw 작업 묶음과 완료 정의

각 단계 안에서 “계약/로직 → 가짜 연결 → 실제 화면/서버 연결 → 검증” 순서로 작은 묶음을 만든다.

1. HANDOFF.md와 대상 파일을 읽고 현재 상태를 재확인한다.
2. 수정할 파일·위치·이유를 먼저 설명하고 코드 이해를 확인한다. 이번 문서 작성은 코드 변경이 아니다.
3. 세 단계 이상이면 update_plan으로 전체 목록을 유지한다. 이 계획 승인 뒤 실행할 때 plan에 이 파일 이름을 넣는다.
4. 단위 테스트 → API/DB 통합 테스트 → 화면 E2E → 필요한 실제 기기 테스트 순서로 검증한다.
5. 요구사항 ID, 변경 경로, 실행 명령/결과, 가짜/실제 연결 여부, 남은 조건을 HANDOFF.md에 남긴다.
6. 승인·실행·검증을 구분하고, 서버/서비스가 없어 막힌 경우 완료 체크하지 않는다.

완료 기준:
- 원문 기능 설명을 실제 화면/저장소에서 수행할 수 있음.
- 정상·실패·빈 데이터·중복·권한·시간 경계 테스트 통과.
- 가짜 어댑터가 아닌 실제 연동 검증 증거가 있음.
- 비용·보안·데이터 전송 정책 합의와 필요한 기기 검증을 마침.

마일스톤:
- M1 단계 3: AI 없이도 메모·일정·할 일을 저장하고 다시 볼 수 있는 기반. 일정 알림 최종 검증은 남음.
- M2 단계 5: 텍스트·음성·문서→분석→확인→저장 흐름.
- M3 단계 8: 프로젝트·근거 기반 비서·일간 브리핑까지.
- M4 단계 10: 교차 대조·선제 알림·확장 3종까지 50건 최종 검증.
